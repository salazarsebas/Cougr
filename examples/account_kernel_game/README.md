# Account-Kernel Game Example

A minimal Soroban game demonstrating session-authorized gameplay using the `account-kernel` piece scaffolded via the Cougr CLI.

## Generation Commands

As required by the Cougr CLI workflow, this project was scaffolded starting from `cougr new` and importing the `account-kernel` piece:

```sh
cougr new account_kernel_game
cd account_kernel_game
cougr add account-kernel
```

> **Note**: The `src/account_kernel.rs` module in this example is the exact, unmodified output generated by `cougr add account-kernel` (`cli/pieces/account-kernel/account_kernel.rs`).

## Architecture & Flow

1. **Session Scope**: An owner account approves a session key via `AccountKernelGame::init_session`. The session is configured with a maximum operation budget (`max_ops`) and an absolute expiration timestamp (`expires_at`), allowing only the `"tap"` action.
2. **Gameplay Action**: The player executes `AccountKernelGame::increment` using the active session key, sequential nonce, and expiration.
3. **Kernel Authorization**: Under the hood, the contract constructs an `AccountKernel` instance and validates the signed session intent against `account_kernel::authorize_action`.
4. **Counter Increment**: Once verified, the instance storage counter is safely incremented.

## Verification & Tests

The contract test suite verifies the end-to-end authorization lifecycle through the game's actual action:
- **`test_increment_allowed`**: Proves an in-policy action increments the counter and advances session state across sequential nonces.
- **`test_increment_expired_session`**: Proves that after the ledger timestamp exceeds `expires_at`, calls to `increment` are rejected and the game state remains unmutated.
- **`test_increment_replayed_nonce`**: Proves that replaying an already consumed nonce (`NonceMismatch`) fails and prevents duplicate execution.

Run tests with Cargo:
```sh
cargo test --package account_kernel_game
```
